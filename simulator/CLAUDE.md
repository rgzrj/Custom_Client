# RM2027 模拟裁判系统项目规则

## 项目目标与边界

本目录维护独立的 Python 本机模拟裁判数据、交互控制台、视频测试发送、故障注入、场景与回放工具。它不是官方裁判系统，也不是操作手客户端。

外层 `simulator/` 是项目目录，内部同名目录是 Python 包。启动入口为本目录 `run-simulator.cmd`，测试与命令均从本目录运行。不依赖父目录规则、启动器、构建文件或客户端源码；正式客户端独立启动后通过本机网络观察模拟数据。

两个项目目前共用父目录隐藏的 Git 历史。该历史不是运行依赖，本次未创建新 Git 仓库。

## 规则与协议来源

优先级为 RM2027 正式规则/通信协议、官方补充说明、官方前瞻、RM2026 历史资料、公开实现参考。引用必须说明具体来源与适用年份；公开代码或素材须先核对许可证，无许可证只读不抄。

目前没有 RM2027 正式通信协议。`rm27.sim.*` JSON、MQTT 测试主题、39001–39004 端口、MPEG-TS 测试容器、六个 HUD 位置与阶段时钟都是项目决策，不得描述为官方事实。不自动推导未经确认的处罚、复活、兑换、飞镖遮挡或控制规则。

后续官方资料由本项目按需独立保存并登记来源，不通过导入客户端代码“继承”规则。

## 安全与通信边界

- 仅服务本机联调，固定环回地址；不得连接、逆向或干扰真实裁判系统和机器人。
- MQTT broker 只读、只接受一个观察客户端，不接收控制主题，不缓存旧裁判数据。
- 不提供真实控制指令，不用模拟状态解除客户端指令门。
- 所有外来 JSON、场景、录像与视频文件视为不可信，保持字段、类型、大小、包结构与时间顺序校验。
- 场景加载只填入编辑器，不自动启动网络、不执行 Python 或 shell；回放备注不得自动打开视频路径。
- 文件记录不覆盖旧记录，达到边界停止并保留已写数据；恢复链路时不得突发重发断流前排队的旧包。

## 工程约束

- 控制台、发包、场景、回放和测试优先使用 Python 标准库；GUI 使用 Tkinter，不新增 PySide、前端框架或外部 broker 依赖。
- OpenCV/NumPy 仅供可选原创视频样本生成工具使用，不是普通运行和测试的必需依赖。
- PyInstaller 及 `requirements-build.txt` 仅用于项目内隔离发布构建环境，不安装到用户全局 Python；发布基线固定，实际 DLL 许可缺失则拒绝分发。
- 网络回归使用系统分配的独立端口，排空/停止必须有总超时；应用默认端口不随测试变化。自检不杀未知进程、不修改网卡。
- `contracts/` 文档与样例独立保存，联调发布显式比较客户端副本；日常运行/单测不依赖客户端源码。
- 比赛状态只有一份规范数据源，HUD 载荷由它派生；阵营切换不交换两队实际状态。
- 网络、文件和回放等待不得阻塞 Tk 主线程；后台线程通过有界队列交互。
- 时间脚本使用单调时钟，故障随机数使用显式种子；注明机器调度仍可能影响出帧结果。
- 保留 UDP、MQTT、裁判数据与视频的独立开关，实际断链与数据过期分别测试。
- `probe` 不是视频；只有实际 TS 字节可用于解码恢复验证。H.264 已验证，H.265 尚未验证。
- 录制的是发送端字节、状态与时间线，不是客户端接收时间、输入、指令门结果或屏幕录像；不把发送端统计冒充接收丢包率和端到端延迟。
