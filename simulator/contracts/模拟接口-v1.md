# 本机模拟接口 v1（非官方）

来源：项目决策，2026-09-30。本文件与固定样例在两个独立项目各保留一份；运行不读取另一项目。它不是 RM2027 正式通信协议，不是 Protobuf，不含真实上行控制。

## 1. 传输与版本

| 链路 | 默认端点 | 内容 |
| --- | --- | --- |
| 裁判 UDP | 127.0.0.1:39001 | 每报文一个 UTF-8 JSON 对象，最多 4096 字节 |
| 裁判 MQTT | 127.0.0.1:39004 | MQTT 3.1.1、QoS 0，主题 rm27/sim/v1/referee，同一 JSON 载荷 |
| 视频探针 UDP | 127.0.0.1:39002 | 包/字节/到达间隔测试，不是视频 |
| 视频解码 UDP | 127.0.0.1:39003 | 合法 MPEG-TS，188 字节 TS 包、每个 UDP 报文最多 7 包 |

应用地址仅环回；测试用系统自动分配端口，不争用默认端口。客户端只在显式开启本机 UDP 视频/MQTT 时使用对应解码/订阅入口。UDP 与 MQTT 的裁判载荷共用序号去重，不要同时灌入两套独立序号流。broker 不接受上行控制，不缓存旧裁判载荷。

载荷 channel 必须是 rm27.sim.v1.referee；不认识的版本拒绝。v1 忽略未知扩展字段，但已知字段类型或范围错误时整包拒绝，不部分更新。可选字段“缺失”有效，“null”无效。JSON 布尔值不算数值，所有数值必须有限，标注整数的字段可为 1.0 但不能为 1.5。

## 2. 必需字段

| 位置/字段 | 类型与边界 |
| --- | --- |
| sequence | 整数 0..9007199254740991 |
| sent_at_unix_ms | 正整数 1..9007199254740991，仅发送时间记录，不用于放宽新鲜度 |
| phase | preparation / self_check / countdown / match / ended |
| telemetry | 对象，以下八个字段全部必需 |
| hp / max_hp | 整数，hp 为 0..1000000，max_hp 为 1..1000000；hp ≤ max_hp |
| chassis_power_w / buffer_energy_j | 数值 0..1000000 |
| barrel_heat / ammo | 整数 0..1000000 |
| latency_ms | 整数 0..60000，模拟展示值，不是链路实测 |
| packet_loss_pct | 数值 0..100，模拟展示值，不是接收丢包统计 |

## 3. 可选 hud 对象

hud 存在时，下列第一组全部必需：

| 字段 | 类型与边界 |
| --- | --- |
| own_team | red / blue；friendly 永远指我方，不随屏幕左右改变语义 |
| friendly_hp / enemy_hp | 长度恰好 6 的数组，每项整数 0..1000000 |
| friendly_positions / enemy_positions | 各 6 个 [x,y]，每轴数值 0..1，项目归一化坐标 |
| friendly_coins / enemy_coins / allowed_shots | 整数 0..1000000 |
| restart_count | 整数 0..1000 |
| pitch_deg / speed_mps | 数值，分别 -45..45、0..100 |

以下是可选扩展：yaw_deg 数值 -180..180；self_index 整数 0..5；level 整数 1..10；shield 与 max_shield 必须同时存在，整数范围分别 0..1000、1..1000 且前者不大于后者；actions 对象必须有 climb、fire、speed_up 三个布尔值。

六个位置固定为哨兵、无人机、步兵3、步兵4、工程、英雄，仅为本项目显示约定，不代表官方阵容。缺失的可选字段显示未知，不保留上一包值。模拟器统一状态转换后的 telemetry.hp 与 friendly_hp[self_index] 一致。

2026-10-01 项目扩展：可选 `hud.structures` 对象，用于基地/前哨 HUD 联调。存在时必须有 `friendly_base`、`enemy_base`、`friendly_outpost`、`enemy_outpost` 四个对象，每个含整数 `hp`（0..1000000）和 `max_hp`（1..1000000），且 hp ≤ max_hp。缺失表示未知，null、布尔值、分数、超限或缺少必需项整包拒绝。旧包仍有效；数据过期或新包省略该扩展时清空旧建筑血量。模拟器规范状态按红/蓝分别保存建筑，切换我方阵营只切换 friendly/enemy 视角；旧场景可不带 structures，不能自动补成满血。默认基地 5000、前哨 1500 **仅为项目演示值，不是官方上限**，不得推导伤害或比赛规则。

地图坐标依旧是项目归一化坐标，尚未与真实场地标定。本地加载历史参考底图不等于拥有正式 RM2027 地图或有效实时定位。

## 4. 可选 event 对象与接收行为

event 的 id、category、text 均必需。id 为 1..48 个 ASCII 字母/数字/连字符/下划线；category 为 system / robot；text 为 1..120 个 UTF-16 单元的可打印 Unicode 文本，禁止换行与控制字符，合法 emoji 可用。

有效裁判载荷到达后，用本机接收时刻刷新 600 ms 定时器；重复或乱序 sequence 不刷新、不更新。过期后重置序号流，HUD 与事件清空，控制仍锁定，因此新的会话可从序号 0 开始。事件按当前保留列表中的 id 去重，最多保留 24 条；不是永久全局去重数据库。

这些阈值都是项目决策。新鲜度分级仅用于显示，不能改变指令门；模拟/回放一律禁止真实控制。

## 5. 诊断读数不能混用

模拟 latency_ms / packet_loss_pct 与发送器故障注入设置不是接收端测量。探针到达缺口表示相邻包静默 ≥250 ms，不等于 RTP/官方分片丢包。探针静默 700 ms 标记断流；实际视频则按连续 700 ms 未收到有效解码帧标记过期。

客户端 frameAgeMs 为最近有效 QVideoSink 帧的年龄；recoveryAfterStaleMs 是“宣布视频过期 → 再收到有效解码帧”的单调时钟间隔，包含故障等待，**不是发送恢复到出帧耗时，更不是相机到屏幕延迟**。未知为 -1。endToEndMeasured 固定 false，缺少两端同步时钟/采集与展示时间标记，不能宣称端到端低延迟已测。

## 6. 同步与验收

固定样例文件 sim-v1-fixtures.json 包含 18 个合法/非法案例：红蓝边界、旧包可选字段、未知扩展、版本/类型/范围错误、事件 emoji/换行，以及建筑零血量/布尔血量/缺少前哨等。它是可执行回归样例，不是涵盖所有可能输入的 JSON Schema。

客户端 C++ 用实际解析器读取本项目样例；Python 验证同样的接受/拒绝结果，并将统一状态产生的包与合法样例比较。改字段时两端同步更新文档/样例并分别测试；破坏兼容性的修改另立版本，不能静默改变 v1。

从任一项目执行 scripts/check-contract.ps1 -ReferenceProject "另一项目的绝对路径"，比较文档与样例 SHA-256。发布联调版本时给 package-windows.ps1 同样的 -ReferenceProject 参数；独立构建不要求另一项目存在，但不提供该参数就没有双端漂移检查。

## 7. 独立模拟雷达坐标（非官方）

这是本机地图联调扩展，不是 RM2027 正式接口，也不认定参赛时允许雷达直接向终端发包。复用环回 UDP 裁判数据监听端口（默认 39001），但独立命名为 `rm27.sim.v1.radar`。不新增官方端口或 MQTT 主题，不携带指令。正式部署需等待通信协议确认信息可用性、来源、坐标系、机器人 ID 和遮挡/处罚规则。

```json
{"channel":"rm27.sim.v1.radar","sequence":0,"sent_at_unix_ms":1790000000000,"red":[{"id":0,"x":0.8,"y":0.7}],"blue":[{"id":1,"x":0.3,"y":0.4}]}
```

- 包最大 4096 字节；`sequence` 为 0..2^53−1 整数，发送时间为 1..2^53−1 整数。发送时间仅元数据，新鲜度由本机接收后的独立 600 ms 定时器决定。
- `red`、`blue` 都必填，是各 0..6 个点的**全量快照**，空数组表示当前无坐标。每点 `id` 为 0..5 整数，同队不重复，只代表当前六个模拟槽位，不是官方机器人 ID。x/y 均为 0..1 有限数字，原点在图像左上，x 向右、y 向下；不对应场地米制坐标，历史参考底图未标定。
- 雷达与裁判序号、过期定时器完全独立；重复/乱序/非法雷达包不刷新任一路，雷达过期后可从序号 0 重新开始。更换监听配置会立即清除旧会话。
- **仅模拟融合策略**：新鲜雷达快照优先提供双方坐标；雷达过期回退新鲜裁判 HUD 坐标；两路都过期则清空。建筑血量、前哨存活、金币等仍只来自新鲜裁判数据。雷达更新不刷新裁判新鲜度、不保留旧建筑血量、不解除控制锁定。
- 有新鲜裁判阵营时据此映射我方/敌方；无裁判数据时使用启动页红蓝预设，未确认阵营时不显示队伍坐标。地图本身不叠加来源说明，只在无坐标时显示“坐标待接入”；模拟模式与控制禁用提示仍在操作界面。
- 独立开发联调命令：在 Python 模拟器项目目录运行 `python simulator/sim_radar.py --duration 30`。可与现有 UDP 或 MQTT 模拟裁判同时运行；该工具不录制，也未加入旧发布 EXE。
- 依据：2026 规则 §5.6.6（PDF 118–120 页）说明雷达坐标经裁判服务器处理及地图显示机制；PDF 122 页和附录 PDF 154 页把具体结构指向独立《通信协议》。2027 前瞻 §2.2.1（PDF 14 页）列出 MQTT+ProtoBuf/UDP 并明确参阅《通信协议》。以上是历史/前瞻依据，**不提供本扩展的正式协议依据**。本扩展字段、阈值和融合优先级均为项目决策。
