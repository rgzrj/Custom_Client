# RM2027 自定义终端

Windows 优先的 Qt 6/QML/C++ 操作手终端，当前用于本机模拟联调与本地视频回放。

## GitHub 源码仓库

源码仓库：<https://github.com/rgzrj/Custom_Client>。仓库包含源码、QML 界面、机器人图片资源、模拟器、测试和学习文档；运行方式见下文。

编译目录、发布包、临时文件、本地视频、下载的 Qt 文档、官方规则 PDF 与本地更改日志 `Edit.md` 不纳入 Git。`规则/` 下的官方文件需自行从官方渠道取得，规则引用与协议确认状态保留在 `CLAUDE.md` 和 `.agents/skills/` 中。本仓库的源码启动需要 Qt 开发环境；普通用户使用下文的 Windows 便携预览包。

## Windows 便携预览包

普通用户解压整个发布 ZIP，双击 `rm27_terminal.exe`，在启动面板选择“离线演练进入”。无需安装 Qt、Python 或编译工具；本地视频回放可直接使用，动态裁判模拟需另行运行模拟器，正式比赛通信仍待协议接入。发布包生成在本地 `dist/`，上传 GitHub Release 后从 Releases 下载；GitHub 的“Download ZIP”下载的是源码。

开发者生成 Release 便携包（旧包保留、不覆盖）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-windows.ps1 -TestVideo .\build-gui\pattern-h264.mp4
```

`-TestVideo` 可省略；提供时运行已有的 GUI/视频回归测试，并将该视频作为 `demo.mp4` 随包附带。仅传入有权分发的原创测试样本。脚本执行 Release 构建、CTest、Qt/QML/FFmpeg/MinGW 部署，生成使用说明、版本与依赖清单、默认配置源码校验、ZIP 和 SHA-256。首次生成后仍需在未安装 Qt 的 Windows 机器上验证；版本清单不会将本机环境隔离测试冒充干净机器验证。

打包需要 Qt Multimedia 的离线文档以附带 FFmpeg 的版权与许可正文。检查 ZIP 校验、解压内容及隔离 Qt 环境后的启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-windows-package.ps1 -Archive "完整发布 ZIP 路径"
```

检查进程不会读取你的真实配置，只在临时目录中创建测试配置和日志；检查目录保留，便于定位问题。

## 启动

在资源管理器中双击 `run-terminal.cmd`。脚本默认使用 `D:\Qt6` 中安装的 Qt MinGW 和 Multimedia，为当前进程设置运行库路径，不修改系统 PATH。首次没有可执行文件时自动构建；代码更新后用下面的命令重建（先关闭客户端）：

```powershell
.\run-terminal.cmd -Build
```

指定本地视频（支持含空格的路径）：

```powershell
.\run-terminal.cmd -Video "D:\videos\test clip.mp4"
```

安装在其他目录时用 `-QtRoot "D:\OtherQt"`。需要 Qt 6.9+、Qt Multimedia、对应 MinGW、CMake、Ninja。这个入口是开发环境启动器，不是独立部署包。

本机视频与 MQTT 同时联调（另开终端启动模拟器，见[模拟器说明](simulator/README.md)）：

```powershell
.\run-terminal.cmd -Build -SimUdpVideo -SimMqtt
```

两个开关都只使用 `127.0.0.1` 项目测试端口；未提供开关时不连接测试 MQTT。该链路不是官方比赛通信，任何模拟状态都不能解锁真实控制。

## 启动面板与链路配置

每次启动都会先出现启动面板，确认链路与模式后才进入终端。

- 只配置本应用自己的端点：裁判数据主机/端口、图传绑定地址与探针端口、本机联调解码端口、本机模拟 MQTT。**不修改 Windows 网卡的 IP、掩码或 DNS**，也不提供这类操作。
- 地址只接受 IPv4 字面量，不解析域名；填错不会产生 DNS 查询，也不会向外部地址发起连接。
- 网卡列表是只读枚举（有线 / 无线 / 虚拟 / 环回、连接状态、IPv4）。只有「有线且拿到可用地址」才算有线链路就绪：蓝牙 PAN 适配器被 Windows 报成 Ethernet 类型，这里按名称归为「虚拟」；169.254 链路本地地址不计入就绪判断。没有有线链路时「进入正式终端」不可用，但离线演练与本机模拟照常可进。
- 默认值全部是本机模拟环回（裁判 39001 / 探针 39002 / 联调解码 39003 / MQTT 39004）。**RM2027 正式地址、端口、MQTT 主题、QoS 与 UDP 分包格式尚未确认，面板不预填、不猜测。**
- 链路预设下拉：本机模拟、本机模拟 + MQTT、**离线哨兵 203.0.113.0/24（无需网络）**、正式链路（占位，待官方协议）。
- 底部「进入终端」固定在面板底部，中段可滚动，1180×680 下不会把按钮挤出画面。
- **配置原子写与自愈**：`connection.ini` 先写临时文件再原子替换，并保留上一份可用配置为 `.bak`；若文件损坏或不是本应用的配置，会被隔离为 `connection.ini.corrupt-<时间戳>`，**优先从 `.bak` 恢复**，否则回落默认值，并在面板上给出提示。
- **链路诊断行**：面板顶部显示 `UDP 探针 N 包 / KiB · 阶段=等待首包|已收包·等待解码|收包→出帧|断流 · 缺口/断流/重同步/来源拒绝 · 静默 xx ms`，末尾固定标注「组装/解码（待官方 UDP 分包格式）」。其中「缺口」是**到达间隔**超过 250 ms 的计数，不是官方分片序号缺口；「来源拒绝」是非环回来源被丢弃的报文数（探针只服务本机联调）。
- **性能读数**：面板与底栏显示出帧率（1 秒窗口）与 GUI 线程调度抖动。抖动超过 150 ms 会记一次「GUI 线程疑似被阻塞」——这条用来保证解码/IO 没有跑回 GUI 线程，而不是只写在注释里。
- **有线输入快捷键表**：面板列出全部动作的按键与文案，两者**同源**（来自 `src/core/input_mapping.*` 的动作表）；所有按键都经同一个输入闸门派发，命令类动作必须先过 `evaluateCommand()`。
- **切源代价提示**：切换画面来源（不加载 / 本地回放 / 本机 UDP 联调）会走最短驻留策略：同源不重启解码，异源在 1500 ms 内不接受再次切换，并在面板显示判断结果。

### 离线哨兵段（无网进入）

- 把「裁判数据主机」填进 **`203.0.113.0/24`**（RFC 5737 文档保留段，公网与内网都不会路由到它），或直接用下列任一入口，即可在**没有网线、没有以太网连接**时进入：
  - 预设下拉选「离线哨兵 203.0.113.0/24（无需网络）」后点「离线演练进入」；
  - 右侧「离线演练进入（203.0.113.0/24）」按钮；
  - 快捷键 `Ctrl+Shift+O`（面板已关闭时同样有效）；
  - 双击面板标题。
- 进入后固定为**模拟**模式，顶部常驻「离线演练 · 哨兵段 203.0.113.0/24 · 非官方链路 · 指令已锁定」横幅，配色与正常模式可区分。`F1` 可重新打开启动面板。
- 该入口**结构上无法下发指令**：`evaluateCommand()` 对模拟/回放模式一律返回 `GateBlock::OfflineMode`，不依赖界面是否禁用；离线期间也禁止切换到可下发模式。
- 只在环回上收数据，不连接任何外部地址、不修改系统网络设置；使用记录（时间 + 哨兵地址）写入本地 `connection.ini`，便于赛后复盘。
- 哨兵段与离线入口属于**项目决策**，不是 RM2027 官方协议内容；正式参赛硬件与网络配置仍以官方规则和正式通信协议为准。

## 当前可以看什么

- 底部“打开本地视频”：全窗口视频底层保持画面比例，支持播放/暂停、进度拖动、片尾重播与循环播放；播放条可用底部中央小标签收起或展开，收起后让出视频视野。非 16:9 视频保留黑边，不裁切侧面视野。
- 透明 HUD：左上角用红/蓝标识明确显示“我方 · 红方/蓝方”，无新鲜阵营数据时显示“我方 · 阵营待确认”；顶部双队伍栏保持我方在右（**我方只列除本车外的 5 台队友**），中央是红青准星与低对比四角参考线，准星左侧是俯仰弧与 `PITCH` 读数，**俯仰弧与右侧对照弧下端所在的水平线上是横向偏航刻度条（`YAW` 读数 + 当前位置标记）**，右侧为双环仪表，左下为血量，右下为地图。队伍与仪表直接浮在视频上，不使用大面积背景框。运行 Python 模拟器后，可看到阵营、双方六台机器人血量、金币、重启次数、**偏航角**、俯仰角、射速、允许发弹量、等级、护盾、动作提示与地图点位动态更新；模拟数据过期后自动恢复未知状态（偏航条整条变暗并显示 `YAW --°`）。使用 `--team red` 可检查红方状态。
- 左侧“选手画面”入口可展开摄像头选择，手动选择本机识别的有线 USB 摄像头或采集卡；选中后选择控件隐藏，点击画面右上角“关闭”即停止采集并收起选手窗。默认只显示小入口，不启用摄像头、不采集音频、不录制。若设备没有出现，检查 Windows 的相机隐私权限和连接状态。
- 选手窗下方的半透明消息区同时显示“系统 / 机器人”事件，每条自带类别标记。Python 模拟器约在第 3 秒发送机器人升级、第 8 秒发送飞镖命中；两类消息均明确标注为“项目模拟消息”，重复 UDP 包不重复显示，数据过期后清空。
- 身份区块除「我方阵营」外还有**「本车机型」下拉**（未指定 / 哨兵 / 无人机 / 步兵3 / 步兵4 / 工程 / 英雄），选中后右侧显示该机型线稿缩略图，选择写入 `connection.ini` 的 `identity/own_robot`，下次启动仍生效。它只是赛前设定：裁判数据到位后以裁判系统为准。
- **机型线稿按名字内置**：队伍栏与左下角自车模块显示的是**按原文件名内置**的机型线稿（`哨兵 / 无人机 / 步兵3 / 步兵4 / 工程 / 英雄`）。两条队伍栏分别贴左右外边、同一行（结构对称），我方只列队友。原图是白底黑线，直接放进深色 HUD 会糊成亮块，所以构建时内置的是 `pitcure/hud/` 下的 HUD 版（透明底 + 白线），由 `python tools/prepare_robot_photos.py` 从原图确定性生成；换图时按原名替换 `pitcure/` 里的文件、重跑一次脚本即可。缺 HUD 版时构建告警并回退原图，资源缺失时界面回退到内置简化线稿。`飞镖.jpg` 本次未内置（等正式协议确认飞镖状态再接）。
- **右侧双环仪表**：外圈为弹速、内圈为允许发弹量，**两条 270° 等宽圆弧**；弹速为红色并随本车机型换量程——**英雄 16 m/s、其余 24 m/s**（项目显示设定，非官方参数），达到量程上限时整条弧填满；中央数字为红色小字。
- **本车随裁判数据动态识别，且不在队伍栏里重复出现**：哪一台是操作手驾驶的「本车」由裁判数据（项目模拟字段 `self_index`，0..5）给出。**我方队伍栏只列 5 台队友**——本车那一台会被移出列表（血量按机型下标取，不会因为少一格而错位），本车自身完全交给左下角自车模块：显示「本车 · <机型>」并换成对应机型线稿。开局配置里可以先挑一台本车（见下），它只用于**裁判数据到达之前**；数据一到就以裁判系统为准，队列表与左下角都会跟着换。数据未给出且未挑选时：六台全列、左下角显示「本车 · 机型待确认」；数据过期后回到该状态，不保留上一次身份。模拟器每 150 包（10 Hz 下约 15 秒）换一台车，便于观察动态换图。
- 等级、护盾和动作高亮目前仅由本机模拟数据驱动，不代表实际控制器输入或官方赛事状态；官方事件流和正式裁判通信仍未接入。无有效数据时显示 `--` 或“待接入”。弹丸余量不等同于允许发弹量。
- 本地视频会显示“回放”和播放状态；暂停与结束保留最后一帧，错误文件清空画面并显示错误。回放期间控制保持锁定。
- 底栏显示**数据新鲜度分级**（新鲜 / 轻微延迟 / 延迟偏大 / 已过期，阈值 300/800/1500 ms）与**出帧率**。分级只用于显示与降级标注：指令放行判断仍是二值的 `referee.fresh`（600 ms 过期），分级不会悄悄放宽安全门。
- **界面占用即拦截**：启动面板、文件对话框、选手画面面板展开时，命令类动作一律被 `GateBlock::UiOccupied` 拦截并自动解除解锁；界面类动作（如关闭面板）仍可派发，否则面板无法收起。
- 动态裁判模拟数据与故障场景：[模拟器说明](simulator/README.md)。原有 39002 UDP 探针只表示收到测试数据；另有显式启用的 39003 本机 MPEG-TS 解码测试链路，不代表官方分包。
- H.264 已用原创样本验证；H.265 和官方比赛图传协议尚待验证/接入。

## 验证

核心与协议测试通过 CTest 运行。视频交互测试使用实际 QML 窗口、Qt Multimedia 和本地样本，测试暂停、进度跳转、循环、结束、错误恢复与控制锁定。

配置 CMake 时设置 `-DRM27_TEST_VIDEO="完整样本路径"`，随后运行：

```powershell
ctest --test-dir build-gui --output-on-failure
```

要把本机 UDP 解码场景也纳入窗口测试，先生成上一节所述的 `.ts` 样本，再设置 `$env:RM27_TEST_TS` 为其完整路径后运行 CTest；未设置时该测试场景会跳过。MQTT 本机订阅、过期与重连测试不需要视频样本。

视频测试会在构建目录输出 `playback-1600x900.png`、`playback-1180x680.png` 和 `hud-design-preview-1180x680.png`；最后一张仅在截图时隐藏合成测试视频，以便检查实际 QML 的 HUD 层级。图像像素尺寸随 Windows DPI 缩放变化。不指定样本时不会将视频交互测试登记到 CTest。

启动面板与离线入口由同一个窗口测试覆盖：每次启动弹出、预设下拉含哨兵段、非哨兵地址不进入离线、哨兵进入后横幅与模拟锁、`F1` 重开面板、`Ctrl+Shift+O` 隐形入口、非法地址被校验挡住，并输出 `start-panel-1180x680.png` 与 `start-panel-offline-1180x680.png`。测试使用 `RM27_SETTINGS_FILE` 指向临时文件，不会读写你真实的启动面板配置。

同一测试程序还覆盖两项链路可靠性用例：`videoLinkDiagnostics` 用真实 UDP 发包验证探针的到达缺口、断流、重同步计数与分阶段诊断（含「组装/解码待官方协议」标注），`connectionConfigRecovery` 验证配置的原子写入、`.bak` 保留、坏文件隔离与从备份恢复。

另有三个用例覆盖界面与输入闸门：`inputGateAndUiOccupancy`（占屏时命令类动作被拦、界面类动作仍可派发、未知动作被拒、动作表提示与按键同源）、`performanceAndFreshness`（新鲜度分级随数据年龄递进到「已过期」、GUI 线程被人为阻塞时报出并计数、恢复后清除）、`sourceSwitchCost`（同源短路、冷却期内换源被拒、非法来源编号被拒）。核心策略（新鲜度分级、输入映射语法、切源策略、界面占用闸门优先级）由无 Qt 依赖的 `rm27_core_policies_tests` 与 `rm27_core_tests` 覆盖。

摄像头硬件烟测是可选项，设置 `RM27_TEST_CAMERA=1` 与 `RM27_TEST_VIDEO` 后运行 `build-gui\rm27_playback_tests.exe optionalCameraSmoke`。它会短暂打开第一台摄像头，检查有效帧与主视频同时运行，再关闭摄像头；不会保存摄像头图像。
