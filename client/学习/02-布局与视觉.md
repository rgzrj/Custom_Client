# 第 2 阶段：让 HUD 贴在视频上，又不挡住视频

预计 3 次，每次 30～40 分钟。学完后，你应该能读懂 HUD 为什么随窗口移动、哪些尺寸会缩放、半透明颜色怎么写，并能判断一次布局修改会不会遮住画面。先完成[第 1 阶段](./01-QML入门.md)即可，不要求会网页前端。

这里的“图像叠加”与你熟悉的 OpenCV 绘制框有一点不同：QML 的 HUD 是单独的界面层，不会写入视频帧像素。以下资料均为已核对的 **Qt 6 官方中文原文**，按顺序只读指定部分即可。

## 第 1 次：定位与图层

读：[使用锚点定位](https://doc.qt.io/qt-6/zh/qtquick-positioning-anchors.html)的开头和“锚点边距和偏移”；再读 [VideoOutput](https://doc.qt.io/qt-6/zh/qml-qtmultimedia-videooutput.html) 的 `fillMode` 与 `contentRect`。`anchors.fill: parent` 是四边贴住父对象；`PreserveAspectFit` 是完整显示视频、不裁掉两侧，宽高比不同时可能留边。

回仓库看 [`qml/Main.qml`](../qml/Main.qml)：`videoViewport` 中，`VideoOutput` 铺满窗口，`HudOverlay` 在它后面声明并同样铺满窗口，所以 HUD 画在视频上方。注意“视频显示对象铺满窗口”不等于“每一个窗口像素都有视频内容”。将来若要把 CV 检测框准确压到目标上，需要按视频实际显示区域换算坐标；这不是本阶段要修改的功能。

## 第 2 次：窗口变小，信息不能挤成一团

读：[Qt Quick 布局概述](https://doc.qt.io/qt-6/zh/qtquicklayouts-overview.html)的“主要功能”“简单布局”和“间距”。记住：`RowLayout` / `ColumnLayout` 会安排直属子项的尺寸与位置；直属子项再自己设置 `anchors` 容易产生几何冲突。普通 `Row` / `Column` 主要负责排列，不会像 Layout 那样分配可伸缩尺寸。

回仓库找三处：

1. [`qml/HudOverlay.qml`](../qml/HudOverlay.qml) 顶部的 `unit: Math.min(width / 1600, height / 900)` 和 `side: width * 0.19`。前者缩放一些 HUD 尺寸，后者让侧边信息宽度跟窗口走；并不是所有字体都随 `unit` 缩放。
2. 同一文件左下区域的 `anchors.bottomMargin: hud.bottomInset + 18`。它使血量区避开底部操作栏和展开的播放条。
3. [`qml/OperatorCamera.qml`](../qml/OperatorCamera.qml) 的 `height`、`clip`、`visible`：未使用时只留小入口，展开时容纳预览与选择控件。`clip: true` 裁掉超出面板边界的子项；它不是“停止摄像头”，停止由 `stopCamera()` 完成。

## 第 3 次：透明，不等于把整块内容淡掉

读：[QML 颜色类型](https://doc.qt.io/qt-6/zh/qml-color.html)的开头，以及 [Item](https://doc.qt.io/qt-6/zh/qml-qtquick-item.html) 的 `opacity`、`visible`、`z` 属性。Qt 的八位十六进制颜色格式是 `#AARRGGBB`：前两位是透明度。例如 HUD 消息底板 `#300A1924` 中的 `30` 是 alpha，约为 19% 不透明；`#B00A1924` 则约为 69% 不透明。只降低底板颜色的 alpha，文字仍可以保持清晰；降低整个父项的 `opacity`，子项文字也会一起变淡。

可选读：[高 DPI](https://doc.qt.io/qt-6/zh/highdpi.html)的“概念模型”。QML 的窗口宽高通常是逻辑尺寸，不要直接拿屏幕物理像素或视频帧分辨率当 HUD 坐标。

## 对照本项目验收（不改代码）

运行 `run-terminal.cmd`，可选打开本地测试视频，分别观察大窗口与缩到最小窗口时的界面。然后用自己的话回答：

1. 为什么 `VideoOutput` 和 `HudOverlay` 都是 `anchors.fill: parent`，却不会变成左右两列？
2. 视频为 4:3、窗口为 16:9 时，`PreserveAspectFit` 会不会裁掉视频侧边？此时视频帧坐标能直接当 HUD 坐标吗？
3. 收起播放条后，`bottomInset` 为什么变化？左下血量区会向哪边移动？
4. 若把消息底板从 `#300A1924` 改成 `#B00A1924`，图传会更容易看见还是更难看见？若改父项 `opacity`，文字会怎样？
5. `visible: false` 与 `stopCamera()` 为什么不是一回事？

能说清前 4 题，就可以进入第 3 阶段的 C++→QML 数据流。这里不修改正式界面，也不把项目模拟坐标误认作官方图传坐标。
