# VT03/VT13 到货联调清单

适用当前 `rm2026-v2.0.0` 适配和固定 MIT RM26_Client `e291f2f65f5a5924509e4e2fe1b148ff9d4b24af`。当前普通客户端的控制权限仍关闭。先验收只读数据和视频，再取得控制来源、权限与失效流程的权威依据。

## 准备与记录

- VT03发送端、VT13接收端、裁判主控、实际相机和电脑；确认主控登记红步兵3。
- 官方客户端、裁判服务、固件和对应通信协议的实际版本。旧版V11/VT12已能解码不证明它实现本版本MQTT接口。
- 保存包的manifest、ZIP SHA-256、电脑/显卡信息和实际配置；现场凭据和抓包不进源码。
- 官方2026通信协议V2.0.0 §2（PDF阅读器45页）给出服务器 `192.168.12.1:3333`、自定义电脑 `192.168.12.2`，红步兵3的十进制MQTT clientID为 `3`，蓝步兵3为 `103`。须核对现场拓扑；电脑本地3333未监听不能判断远端服务器是否提供服务。
- 视频协议给出UDP3334。绑定网卡、实际发送来源和分片从0还是1编号需要确认。程序只使用明确配置，不修改电脑网络或配置官方服务。

## 1. 官方配对与镜头

非日本地区按VT03/VT13手册对频章节（阅读器16页、印刷15页）：发送端接主控并通电，接收端开机；主控“模块设置→图传对频”。接收端长按电源键约2秒至提示音，松开，再长按约2秒；核对发送端绿灯1Hz、接收端两声提示后静音。日本地区按对应机器人ID及官方客户端登录流程操作。

先用匹配版本官方客户端观察红步兵3相机前的可辨认动作，确认实际镜头并记录结果。程序的人工确认只记录操作员报告，不执行硬件对频、不认证相机身份。电脑自动对频仍需公开接口或授权SDK。

## 2. 只读MQTT

在便携包目录运行，地址/端口需与已确认的服务一致：

```powershell
./rm27_terminal.exe --protocol rm2026-v2.0.0 `
    --mqtt-host 192.168.12.1 --mqtt-port 3333 --robot-id 3
```

依次核对CONNECT/CONNACK、全部24个已核验主题的SUBACK、RobotStaticStatus报告身份、HP/允许发弹量/金币/阶段。请求ID和报告ID分开记录；报告ID不是操作者认证。缺字段显示未知，显式0显示0，不应出现本地默认血量或倒计时。

停数据但保持视频、停MQTT服务再恢复，检查逐主题1500ms过期清空、断线清空和5s重订阅。时间为项目门槛，不能替代官方时序。RadarInfoToClient外层schema仍冲突，未订阅，不把24主题通过写成全部25个官方下行完成。

F1 展开“诊断详情”后，在可滚动区域查看裁判连接/全部订阅确认、请求与新鲜报告 ID、新鲜主题数量、未收到或已过期主题及最近错误。未收到与已过期合并显示，不推断某个主题必须持续上报；RadarInfoToClient 单列未订阅。诊断为只读展示，不连接新端点、不开放控制，也不默认记录完整报文。

## 3. 原生HEVC到现有UI

`$localIPv4`、`$officialSourceIPv4`、`$confirmedFragmentBase` 必须填现场确认值；分片起始只能0或1，端口3334也须核对实际输出。完成第1步后才传 `--pairing-confirmed`：

```powershell
./rm27_terminal.exe --protocol rm2026-v2.0.0 `
    --mqtt-host 192.168.12.1 --mqtt-port 3333 --robot-id 3 `
    --hevc-udp --video-bind $localIPv4 --video-source $officialSourceIPv4 `
    --video-port 3334 --fragment-base $confirmedFragmentBase --allow-network-video `
    --pairing-robot-id 3 --pairing-region global --pairing-confirmed
```

按“UDP收包→完整组帧→HEVC解码→有效QVideoSink帧→UI显示”定位故障。收包不等于出帧；只有视频而没有报告时身份仍未知。新鲜报告不匹配目标会停止旧视频，重试须新建会话。

核对断流700ms清旧画面、丢片后等待参数/关键帧、正确来源恢复，以及MQTT/视频各自独立断链。设备拔插/断电后核对官方重新配对或登录要求，不沿用旧会话。既有视频诊断和 `log/rm27-run-*.log` 记录状态变化；`--diagnostics-json` 仅用于环回合成测试，正式网络入口不支持，普通日志也不默认保存完整报文。

## 4. 控制开放前的外部依据与后续实现

| 缺口 | 需要的依据 / 后续工作 |
| --- | --- |
| 官方/自定义键鼠独占来源 | 对应官方版本的选择、确认、会话失效和切源流程；目前schema/固定开源没有已核验的确认接口 |
| 完整业务权限 | 角色/注册/阶段/区域/配额/远程参数/机关机会/部署冷却及跨机器人权限；请求ID和PUBACK不能建立权限 |
| 处罚解除与遮挡 | 权威解除、断线/重启恢复及视频/地图/UI遮挡要求；当前持续约束不能用零、缺失或断线清除 |
| 地图/雷达 | RadarInfoToClient外层schema澄清、坐标原点/方向/单位、场地标定和地图操作角色许可 |
| 操作入口与尚未知的参数 | F1面板“赛事操作与参数”已接性能、部署、装配、普通弹量兑换、复活、机关、飞镖、哨兵和空支援；普通权限仍关闭。远程补给参数、自定义控制字节应用格式、地图角色/标定须先取得依据 |

取得证据后再实现对应权限/入口，并安排明确的实机操作范围。保留统一指令门、限频和失焦/释放/遮挡/断线清旧输入。分别记录本地排队、broker PUBACK、赛事接受及机器人执行；无唯一请求ID的报告不能自动关联某一次请求，送达未知不能自动重发。

赛事面板与 F1 诊断显示“最近入队赛事请求”的工作线程等待、传输等待、MQTT 确认、送达未知、过期或取消。只跟踪最近一次入队请求；后续键鼠的 ACK 不会更新该请求的结果。界面同时单列包含键鼠的会话汇总；本地被拒绝的操作仍显示最近操作原因，不替换成旧请求成功。MQTT 确认仍不代表赛事接受或执行；重建 backend 会话或切入离线/回放后不沿用旧发送状态。

现有HUD已显示枪口热量和缓冲能量，允许发弹量仍与物理余弹分开。赛事参数面板按明确选择提交；打开面板占屏停止输入，缺匹配新鲜身份不能提交，身份改变/断线/过期会关闭并清空。面板的“不更改”表示省略字段，哨兵“自动控制”是显式0，两者不同；界面选择不注册操作者、不改变硬件角色、不建立控制来源或授权。

数量键盘编辑与直接点击提交已作交互检查；17mm非10的倍数在界面禁用提交，后端校验继续保留。面板显示前初始化目标和草稿，避免占屏状态通知误关新面板；拒绝后清空重选，不重放旧参数。小窗口参数区停在内容边界，末尾参数可滚动到完整可见；容器缩放检查不能替代现场操作权限/执行验收。

## 5. 实机性能与发布验收

Windows 控制输入使用前台窗口的 Raw Input 相对鼠标移动，已有灵敏度预设直接乘控制量（100=×1，范围10–300）。低灵敏度保留小数余量；滚轮仍沿用原始角度增量。打开面板、失焦、隐藏、切源或关门时释放鼠标抓取/注册、恢复光标并清旧增量；重新捕获不接收此前排队的移动。此接线不提供控制来源或业务权限。非 Windows 的窗口坐标差只作可移植回归，未声称完成该平台的无限相对捕获。

捕获建立及原始输入处理都会核验 Windows 实际前台窗口，Qt 的逻辑激活标志不单独作为依据。软件检查覆盖增益/小数累计、系统注册与释放、旧 Qt 移动不重复计入、畸形输入关门；桌面 SendInput 注入会混入真实鼠标事件与前台切换，不用它的总计数冒充确定性的原始移动或硬件边界验收。

系统实现依据：[Microsoft Raw Input 注册](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerrawinputdevices)、[前台接收与注册标志](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawinputdevice)、[Qt 原生事件过滤](https://doc.qt.io/qt-6/qabstractnativeeventfilter.html)。增益、余量、捕获生命周期与旧消息清理为项目决策。固定开源 MainWindow 的屏幕坐标差/光标移动只作对照，不套用其不同的灵敏度滑块曲线。

测实际分辨率/帧率、1080p60、长时CPU/GPU/内存/队列/GUI抖动、重复断电/断网恢复、输入灵敏度和持续75Hz。相机到屏幕的端到端延迟需要现场计时；解码/提交耗时和显示FPS不等于端到端延迟。本机色条320×180/30fps只证明软件链路。

另一台没有Qt/编译器的干净Windows需完整解压运行并记录结果；本机隔离PATH检查不能替代，完成前 `cleanMachineVerified` 保持false。旧发布包及迁移前Git回退点保留。
