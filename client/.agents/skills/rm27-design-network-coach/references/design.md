# 设计组织与 AI 沟通指南

由项目原创专题《设计术语与 AI 协作》整理。适用于当前视频优先 HUD；这里的示例不是统一适用于所有产品的设计规范。外部依据与阅读顺序见 [readings.md](readings.md)。

## 把感受转换为设计问题

先用普通话说清影响，再引入术语；不要求用户先背词表。

| 中文 / 英文 | 用来判断什么 | HUD 里的表达 |
| --- | --- | --- |
| 信息架构 / Information Architecture | 内容怎样分类、功能怎样被找到 | 连接设置、消息和操作状态分别组织 |
| 视觉层级 / Visual Hierarchy | 应该先看什么 | 视频与异常优先，次要说明弱化 |
| 视觉权重 / Visual Weight | 谁最抢注意力 | 降低装饰圆弧的亮度，不顺带缩小读数 |
| 亲密性 / Proximity | 哪些内容属于一组 | 相关读数靠近，用间距分组 |
| 对齐 / Alignment | 排列是否稳定 | 标签共用边线，数值按统一规则对齐 |
| 留白 / White Space | 是否有呼吸空间 | HUD 间露出的视频也是留白 |
| 排版 / Typography | 字号、字重、行高如何配合 | 区分关键数字、标签、说明，并保持同级一致 |
| 对比 / Contrast | 是否能辨认与区分类别 | 明暗视频上文字都能读，不只看纯色背景 |
| 渐进式披露 / Progressive Disclosure | 次级工具什么时候出现 | 摄像头选择与回放工具按需展开，告警不隐藏 |
| 设计变量 / Design Tokens | 样式值是否能统一复用 | 复用现有 Theme 的字号、间距、颜色，不另建框架 |

“高级感”先落实到一致性、可读性与信息轻重，不把霓虹、模糊或复杂动效默认当成解决办法。参考图要区分“还原结构”和“仅借鉴某种视觉特征”。

## 以任务组织信息

先确认当前任务是瞄准、移动、查看状态还是排障，再判断哪些信息必须持续可见：

- 主任务：保留视频中央及侧方视野，必要辅助不和画面竞争。
- 安全与异常：断流、过期、控制锁定必须明确；不知道的数据不能沿用旧值装成实时。
- 相关读数：按关联性靠近，突出数值，单位和标签辅助识别。
- 次级工具：设置、摄像头选择与播放条按需出现，收起后布局自然衔接。

透明化优先减弱底板、边框与装饰，保留关键文字对比。阵营用“我方·红/蓝”文字辅助确认，不只依赖颜色。系统与机器人消息可并列分类，不能为了整洁漏掉其中一类。

## 截图评审的最小输出

选择会影响当前任务的主要问题，用以下形式表达，不把看不清的文字猜成事实：

> 位置 → 可观察的现象 → 对操作的影响 → 建议 → 不能改动的内容 → 怎样验证。

例如：“右侧圆弧比关键数字更抢眼，分散视频注意力。先弱化装饰亮度并统一标签对齐，保留数值大小和地图位置；在明、暗视频上复核可读性。”

用户只说“挤”时，分别检查间距、字号层级、固定尺寸、重复边框和占屏工具。不同时改变所有尺寸；无截图或尺寸信息时，先说明判断依据不足，不伪造量化结果。

## 六段式需求说明

帮助用户填写；它是沟通模板，不是自动修改授权：

```text
【任务与用户】Qt/QML 图传操作手终端，本次只处理哪个区域、哪项任务？
【当前问题】位置、现象、影响；截图编号或实际操作是什么？
【保持不变】哪些功能、布局、通信含义与控制边界不能动？
【视觉方向与参考】参考图具体借鉴什么？字号、间距、对齐、底板怎样调整？
【禁止与约束】不加大面积不透明框，不遮挡视野，不牺牲告警与文字可读性。
【交付与验收】先评审还是直接实施？窗口、视频背景与异常状态怎样检查？
```

视觉方案有真实取舍时给出少量选项，例如“更少遮挡”和“读数更醒目”。用户已经明确选择时，不反复重新审批，也不擅自扩大成整套重设计。

## 分开验收三个目标

| 目标 | 证据 | 常见误判 |
| --- | --- | --- |
| 美观与可用 | 层级、对齐、可读性、遮挡与操作场景 | 一张设计稿等于实际可用 |
| GUI 顺滑 | 帧时间、抖动、阻塞及真实视频与 HUD 同时运行 | 动画流畅等于图传延迟低 |
| 图传低延迟 | 有明确起止点的采集/发送至显示测量 | FPS 或模拟 latency 字段等于端到端测量 |

60 FPS 每帧约 16.7ms 是刷新预算示例，不是赛事端到端延迟指标。性能问题先找证据，不因代码更短或写了“硬件加速”就宣称提升。

验收按改动挑选必要场景：大/小逻辑窗口、高 DPI、明/暗/复杂视频背景、工具展开收起、系统与机器人消息并存、红蓝及未知身份、正常/缺数据/过期/恢复。区分“建议检查”与“实际检查通过”。

## 三个小练习

1. 标注截图中的三个区域：信息优先级、对应术语、是否遮挡视频。通过标准是能解释影响，不只是说“丑”。
2. 用六段式说明只描述一个区域。通过标准是别人知道改哪里、什么保持不变、怎样算改好。
3. 写出正常和异常验收场景。通过标准是能区分视觉效果、交互可靠性与性能证据。

每次只推进用户当前需要的练习，不自动启动程序或修改文件。已确认的视觉约定可以记录；尚未验证的偏好不升级成全仓库硬规则。
