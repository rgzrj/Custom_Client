当前后端迁移以 ClearWei/RM26_Client 固定提交为基线，保留现有 UI 设计，仅开发 VT03/VT13。M0 已核验 35 个消息定义；M1 已把开源 MQTT/NetworkManager/GameData 接入普通客户端，订阅 24 个已核验下行主题并接到现有 HUD。完整状态和后续验收见 [迁移清单](docs/upstream-migration.md) 与 [CLAUDE.md](CLAUDE.md#当前迁移目标与下一步任务2026-10-11)。实物未到，软件接入不代表现场或 RM2027 验收。

M3 已完成11类上行的有类型接口、统一发送门、异步 PUBACK 与窗口键鼠采集接线。工作线程最多8条在途消息，输入只保留最新一份和一份优先释放；失焦、遮挡、切源、断线或输入过期清旧状态。普通客户端的业务权限门尚未放行，操作控制仍锁定；已增加发送时的角色、阶段、连接/上场/存活、复活资格/余额、装配步骤和空中支援费用检查；仍缺输入来源授权、处罚解除、部分操作身份/区域/配额依据，保留现有UI。broker确认与赛事接受/机器人执行分开记录，详见[迁移记录](docs/upstream-migration.md)。

复活快捷键已接：`Y`请求免费复活、`Shift+F1`请求付费复活；`F1`继续打开启动面板。界面占用时禁用，按住不自动重复。请求仍受角色/死亡/pending/资格/费用及完整权限门约束；当前普通操作权限未开放，按键会说明未发送，排队/PUBACK均不代表复活成功。

事件排队后资格失效或过期，只丢弃该事件；保留键鼠前仍检查当前真实身份、比赛和输入权限。暂停、身份变化、死亡、断线或输入过期继续停止控制。诊断`commands.event_status`/`events_rejected`记录工作线程事件拒绝和过期，独立于键鼠的broker确认，不是机器人执行回执。

普通启动停在现有启动面板，填写 MQTT 地址/端口、启用 MQTT、选择红/蓝方和机型后才连接；红步兵 3 请求 ID `3`，蓝步兵 3 请求 `103`。界面本车身份以收到的报告为准，选择机型不切相机、不替代官方对频。高级设置中的旧模拟 UDP 参数不参与 RM2026 数据连接。离线演练/本地回放会停止这条连接并保持控制锁定。

明确端点也可从客户端目录用 `run-terminal.cmd -Protocol rm2026-v2.0.0 -MqttHost <已确认IPv4> -MqttPort <已确认端口> -RobotId 3` 启动。本机对端加 `-ProtocolTest`，地址只能为 `127.0.0.1`；`-DiagnosticsJson -DurationMs 10000` 仅用于本机诊断。程序不自建 broker，不扫描或配置网卡。普通构建默认启用 `RM27_UPSTREAM_BACKEND`；新增依赖从固定源码编译，开发需 protoc 29.3（CMake `RM2026_PROTOC`），发布运行不需 Python/protoc。

普通入口已接开源 HEVC 解码后端（M2），指令按 M3 接入。`RadarInfoToClient` 因官方外层定义歧义未订阅；新增主题的原始有效字段可在本机诊断的 `reports` 树核验，缺少现有 UI 展示入口的功能见迁移清单。

## 普通入口的 RM2026 HEVC 图传

`run-terminal.cmd -OfficialUdpVideo` 现在运行普通 `build-gui/rm27_terminal.exe`，直接将开源 HevcDecoder 的图像送现有 VideoOutput。布局、准星、字体、颜色和 PreserveAspectFit 保持；不转码，不调用 DJI FFmpeg，不另开播放器。视频可独立运行，也可和上面的 MQTT 配置一起运行。

显式指定 `-BindAddress <本机已确认IPv4> -SourceAddress <官方输出已确认源IPv4> -VideoPort <已确认端口> -FragmentBase 0或1`；非环回再加 `-AllowNetworkVideo`。本机人工对端用 `-ProtocolTest`，监听与来源只能为 127.0.0.1。普通启动不会自动监听、猜源、修改网卡或发对频命令。

2026通信V2.0.0 §2规定 UDP3334、HEVC、8字节大端2/2/4包头、包长≤1400；分片起始0/1和Annex-B/参数集是当前适配的显式假设，需实物核验。视频线程只保留最新一张待提交图像，GUI每16ms取最新；完整组帧后才解码，缺片/序号缺口重置并等关键帧。700ms没有有效画面就清旧帧并标过期；恢复不需要重启整个程序。MQTT与视频各自断链，身份配置/报告身份改变、离线/回放切换清旧视频。阈值和资源上限是项目决策，控制仍禁用。

FFmpeg开发依赖见 [固定公共头与来源](third_party/ffmpeg-7.1.5/README.md)，Windows MinGW直接链接同版Qt LGPL共享DLL；源码归档已放在用户指定的 Huge Mas/开源/tmp。开发/打包不依赖外部开源目录。本机人工色条320x180/30fps验证不代表VT13配对、现场图传或1080p60验收。启动面板的模拟UDP参数不启动这条实际HEVC接收链路，现场参数暂走上述显式启动入口。

人工配对参数已接普通入口：`-PairingRobotId 3 -PairingRegion global`，完成官方对频后才加 `-PairingConfirmed`。MQTT 请求身份必须与配对目标一致；`-ProtocolTest`、合成 HUD 和回放不能创建硬件配对会话。报告身份来自新鲜裁判报文，缺失/过期为未知，不匹配会停止旧视频。详情见[配对说明](tools/README-pairing.md)。旧独立视频脚本、VIDEO_HUD 分支、HistoricalVideoReceiver 与第二 UDP 解码端口已删除；LOCAL 合成 HEVC 使用同一个直接解码后端。

## RM2026 通信参考（独立历史版本）

按用户提供的 2026 V2.0.0 通信协议建立了独立[版本目录与验收说明](contracts/rm2026-v2.0.0/README.md)：11 个接收 Protobuf 消息、3 个离线发送消息定义、Google 运行库解析/每主题过期检查、仅环回地址的 Python 与原生 C++ MQTT 只读参考，以及 C++ UDP 图传包头与有界分片重组测试。原生依赖用固定 MinGW 编译，运行无需 Python，独立目标默认关闭；已验收订阅/QoS1/断线清空/重连/订阅超时，并提供十类独立类型化快照（缺失/过期为未知，身份变化清缓存）。新增显式本机测试 HUD 映射，正常启动及发布仍不启用历史适配器；正式网络资源防护、实物 HEVC 图传与真实控制发布未完成。Qt Release 不增加 Python 依赖。雷达 schema 与视频分片假设等未确认项明确列在版本说明中，不能标为 RM2027 正式协议。

比赛/判罚只读映射已补：保留阶段、暂停、得分、时间、判罚类型/时长/数量，缺失/未知值不补造；仅结算阶段提供有效胜者和结束原因。判罚过期或零时长不代表解除处罚，尚未接入遮挡或指令安全门，仍不进入正常 HUD。

模块/复活只读映射已补：11 个模块区分离线、在线与安装不规范离线，保留未知码；6 个复活字段保留缺失、false、零值和原始读条。模块在线不代表实时视频，报告复活资格不等于指令放行；不自动复活，仍只在独立历史本机探针验收。

原生历史路径已补包体分配前限长、结构检查和每秒包数/字节预算；超限断开清值后可重订阅。异常输入与事件回归见[第十二阶段](contracts/rm2026-v2.0.0/README.md#原生入站防护与历史消息区第十二阶段)。仍限制环回，不是完整安全审计。处罚权威解除信号、正式雷达 schema/场地标定有缺口；本轮暂缓实物图传，不凭模拟测试宣布上场可用。

## Windows 便携预览包

普通用户解压整个发布 ZIP，双击 `rm27_terminal.exe`，在启动面板选择“离线演练进入”。无需安装 Qt、Python 或编译工具；本地视频回放可直接使用，动态裁判模拟需另行运行模拟器，正式比赛通信仍待协议接入。发布包生成在本地 `dist/`，上传 GitHub Release 后从 Releases 下载；GitHub 的“Download ZIP”下载的是源码。

开发者生成 Release 便携包（旧包保留、不覆盖）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package-windows.ps1 -TestVideo .\video\pattern-h264.mp4 -TestHevc .\build-video-fixtures\rm27-test-pattern.hevc -TestTs .\video\console-h264-valid.ts
```

完整视频验收应显式提供三种测试样本；省略时将对应CMake缓存清空，manifest.testFixtures如实记录缺少的覆盖。TestVideo还作为demo.mp4随包附带，HEVC/TS只作构建测试，不随包分发。仅传入有权分发的原创测试样本。脚本执行Release构建、CTest、Qt/QML/FFmpeg/MinGW部署，再复用check-windows-package在无开发PATH、无Qt插件路径及无原配置的环境检查部署目录、实际Windows GUI与DLL来源；通过后生成来源/协议/覆盖信息、依赖清单、ZIP和SHA-256。首次生成后仍需在未安装Qt的Windows机器上验证，cleanMachineVerified保持false。

打包需要 Qt Multimedia 的离线文档以附带 FFmpeg 的版权与许可正文。检查 ZIP 校验、解压内容及隔离 Qt 环境后的启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-windows-package.ps1 -Archive "完整发布 ZIP 路径"
```

检查进程不会读取你的真实配置，只在临时目录中创建测试配置和日志；检查目录保留，便于定位问题。

## 启动

在资源管理器中双击 `run-terminal.cmd`。脚本默认使用 `D:\Qt6` 中安装的 Qt MinGW 和 Multimedia，为当前进程设置运行库路径，不修改系统 PATH。首次没有可执行文件时自动构建；代码更新后用下面的命令重建（先关闭客户端）：

```powershell
.\run-terminal.cmd -Build
```

指定本地视频（支持含空格的路径）：

```powershell
.\run-terminal.cmd -Video "D:\videos\test clip.mp4"
```

安装在其他目录时用 `-QtRoot "D:\OtherQt"`。开发启动/打包固定 **Qt 6.11.2 + MinGW 13.1.0 + CMake 3.30.5 + Ninja 1.12.1**，需包含 Qt Multimedia；清单见 [toolchain.json](toolchain.json)。C++ 源码最低 Qt 仍为 6.9，但不自动选择未知新版工具链。升级版本先重验再修改固定清单。这个入口是开发环境启动器，不是独立部署包。

只检查环境、中文报告缺少的组件和默认端口占用（不启动窗口）：

```powershell
.\run-terminal.cmd -CheckOnly
```

本机模拟契约见 [contracts/模拟接口-v1.md](contracts/模拟接口-v1.md)。联调发布前运行 `scripts/check-contract.ps1 -ReferenceProject "模拟器项目路径"`；打包脚本也接受 `-ReferenceProject`，检查文档/样例是否同步。不提供该参数时保持独立打包，但没有跨项目漂移门禁。

本机视频与 MQTT 同时联调（另开终端启动模拟器，见[模拟器说明](../simulator/README.md)）：

```powershell
.\run-terminal.cmd -Build -SimUdpVideo -SimMqtt
```

两个开关都只使用 `127.0.0.1` 项目测试端口；未提供开关时不连接测试 MQTT。该链路不是官方比赛通信，任何模拟状态都不能解锁真实控制。

每次启动都会先出现启动面板，确认链路与模式后才进入终端。

- 只配置本应用自己的端点：裁判数据主机/端口、图传绑定地址与探针端口、本机联调解码端口、本机模拟 MQTT。**不修改 Windows 网卡的 IP、掩码或 DNS**，也不提供这类操作。
- 地址只接受 IPv4 字面量，不解析域名；填错不会产生 DNS 查询，也不会向外部地址发起连接。
- 网卡列表是只读枚举（有线 / 无线 / 虚拟 / 环回、连接状态、IPv4）。只有「有线且拿到可用地址」才算有线链路就绪：蓝牙 PAN 适配器被 Windows 报成 Ethernet 类型，这里按名称归为「虚拟」；169.254 链路本地地址不计入就绪判断。没有有线链路时「进入正式终端」不可用，但离线演练与本机模拟照常可进。
- 默认值全部是本机模拟环回（裁判 39001 / 探针 39002 / 联调解码 39003 / MQTT 39004）。**RM2027 正式地址、端口、MQTT 主题、QoS 与 UDP 分包格式尚未确认，面板不预填、不猜测。**
- 链路预设下拉：本机模拟、本机模拟 + MQTT、**离线哨兵 203.0.113.0/24（无需网络）**、正式链路（占位，待官方协议）。
- 底部「进入终端」固定在面板底部，中段可滚动，1180×680 下不会把按钮挤出画面。
- **配置原子写与自愈**：`connection.ini` 先写临时文件再原子替换，并保留上一份可用配置为 `.bak`；若文件损坏或不是本应用的配置，会被隔离为 `connection.ini.corrupt-<时间戳>`，**优先从 `.bak` 恢复**，否则回落默认值，并在面板上给出提示。
- **链路诊断行**：面板顶部显示 `UDP 探针 N 包 / KiB · 阶段=等待首包|已收包·等待解码|收包→出帧|断流 · 缺口/断流/重同步/来源拒绝 · 静默 xx ms`，末尾固定标注「组装/解码（待官方 UDP 分包格式）」。其中「缺口」是**到达间隔**超过 250 ms 的计数，不是官方分片序号缺口；「来源拒绝」是非环回来源被丢弃的报文数（探针只服务本机联调）。
- **性能读数**：面板与底栏显示出帧率（1 秒窗口）与 GUI 线程调度抖动。抖动超过 150 ms 会记一次「GUI 线程疑似被阻塞」——这条用来保证解码/IO 没有跑回 GUI 线程，而不是只写在注释里。
- **有线输入快捷键表**：面板列出全部动作的按键与文案，两者**同源**（来自 `src/core/input_mapping.*` 的动作表）；所有按键都经同一个输入闸门派发，命令类动作必须先过 `evaluateCommand()`。
- **切源代价提示**：切换画面来源（不加载 / 本地回放 / 本机 UDP 联调）会走最短驻留策略：重复选择 UDP 来源不重启解码，异类来源在 1500 ms 内不接受再次切换，并在面板显示判断结果。“打开本地视频”与 Ctrl+O 可反复选片（包括重新播放同一文件）；只有确认文件后才切换，取消保留当前来源、暂停状态和进度，不误标为回放。

  - 预设下拉选「离线哨兵 203.0.113.0/24（无需网络）」后点「离线演练进入」；
  - 右侧「离线演练进入（203.0.113.0/24）」按钮；

### 日志与临时截图

每次启动主终端，会在 [log/](log/) 创建独立的 UTF-8 日志，记录启动、Qt 警告以及裁判/视频新鲜度和控制锁定状态的变化；合成报文演示另写 `rm27-demo-*.log`，记录阶段和子程序错误输出，控制台仍保持原有 JSON 摘要。默认不录制报文正文或完整状态快照。

窗口测试的新截图统一放在 [pitcure/temp/](pitcure/temp/)，文件名带时间、进程与唯一会话标记，避免并发覆盖。启动时后台清理 7 天前、专用命名的本项目生成文件；活动日志、未知文件、旧式截图、正式素材和 `Edit.md` 不清理。日志单文件最多 4 MiB，写盘不在 GUI 线程；强制结束进程可能丢失末尾，不能当作完整崩溃记录。

以上路径不依赖启动工作目录。源码构建使用 `client` 根目录，便携包使用 exe 所在目录（解压到可写目录）；无法写日志不妨碍启动。测试隔离可设置绝对路径 `RM27_ARTIFACT_ROOT`。这是新增输出约定，不迁移已有文件，也不改变 CTest/CMake 的构建日志位置。

- 底部“打开本地视频”：全窗口视频底层保持画面比例，支持播放/暂停、进度拖动、片尾重播与循环播放；播放条可用底部中央小标签收起或展开，收起后让出视频视野。非 16:9 视频保留黑边，不裁切侧面视野。

- 本地视频会显示“回放”和播放状态；暂停与结束保留最后一帧，错误文件清空画面并显示错误。回放期间控制保持锁定。
- 底栏显示**数据新鲜度分级**（新鲜 / 轻微延迟 / 延迟偏大 / 已过期，阈值 300/800/1500 ms）与**出帧率**。分级只用于显示与降级标注：指令放行判断仍是二值的 `referee.fresh`（600 ms 过期），分级不会悄悄放宽安全门。
- **界面占用即拦截**：启动面板、文件对话框、选手画面面板展开时，命令类动作一律被 `GateBlock::UiOccupied` 拦截并自动解除解锁；界面类动作（如关闭面板）仍可派发，否则面板无法收起。
- 动态裁判模拟数据与故障场景：[模拟器说明](../simulator/README.md)。原有 39002 UDP 探针只表示收到测试数据；另有显式启用的 39003 本机 MPEG-TS 解码测试链路，不代表官方分包。
- H.264 已用原创样本验证；H.265 和官方比赛图传协议尚待验证/接入。

### 模拟值与实测读数

HUD 的“模拟延迟”“模拟丢包”来自模拟 JSON，仅用于展示，不能当成网络测速。诊断中新增 `frameAgeMs`（最近有效 sink 帧年龄）与 `recoveryAfterStaleMs`（宣布视频过期到下一有效帧，单调时钟计时，包含故障等待）。未知时为 -1；该恢复间隔不是恢复发送到出帧，也不是相机到屏幕耗时。`endToEndMeasured=false`，文案明确“端到端未测”。探针缺口/断流与实际解码帧分别观测，不混成官方分片丢包率。

环境隔离检查不能替代第二台未安装 Qt 的电脑验收，操作见 [packaging/验收清单.md](packaging/验收清单.md)。新版包尚未上传 GitHub 时，只能从本机 dist 获取，不将旧 Release 描述成新版本。

## 验证

核心与协议测试通过 CTest 运行。视频交互测试使用实际 QML 窗口、Qt Multimedia 和本地样本，测试暂停、进度跳转、循环、结束、错误恢复与控制锁定。

客户端窗口测试每例申请独立 UDP 端口，并使用唯一临时配置目录；不监听/发向默认视频 39003，不删除其他测试实例的配置。MQTT 测试也由系统分配端口。申请后立即交给接收对象绑定，竞争时检查会失败，不自动停掉占用者；建议不同构建目录运行并发测试，避免截图输出覆盖。

配置 CMake 时设置 `-DRM27_TEST_VIDEO="完整样本路径"`，随后运行：

```powershell
ctest --test-dir build-gui --output-on-failure
```

要把本机 UDP 解码场景也纳入窗口测试，准备合法的 `.ts` 样本，再设置 `$env:RM27_TEST_TS` 为其完整路径后运行 CTest；未设置时该测试场景会跳过。MQTT 本机订阅、过期与重连测试不需要视频样本。

视频测试会在 `pitcure/temp/` 输出 `rm27-preview-<会话>-playback-1600x900.png`、`rm27-preview-<会话>-playback-1180x680.png` 和 `rm27-preview-<会话>-hud-design-preview-1180x680.png`；最后一张仅在截图时隐藏合成测试视频，以便检查实际 QML 的 HUD 层级。图像像素尺寸随 Windows DPI 缩放变化。不指定样本时不会将视频交互测试登记到 CTest。

启动面板与离线入口由同一个窗口测试覆盖：每次启动弹出、预设下拉含哨兵段、非哨兵地址不进入离线、哨兵进入后横幅与模拟锁、`F1` 重开面板、`Ctrl+Shift+O` 隐形入口、非法地址被校验挡住，并输出 `start-panel-1180x680.png` 与 `start-panel-offline-1180x680.png`。测试使用 `RM27_SETTINGS_FILE` 指向临时文件，不会读写你真实的启动面板配置。

同一测试程序还覆盖两项链路可靠性用例：`videoLinkDiagnostics` 用真实 UDP 发包验证探针的到达缺口、断流、重同步计数与分阶段诊断（含「组装/解码待官方协议」标注），`connectionConfigRecovery` 验证配置的原子写入、`.bak` 保留、坏文件隔离与从备份恢复。

`rm27_ui_layout_tests` 单独检查 1180×680、1600×900、2560×1440 的 HUD 几何，并使用缺失字体目录复现回退后的文字宽度变化。动作提示按实际文字边界避开地图；隐藏地图后恢复原来的低位。保留水平文字、斜线首字排列、中央留空和圆弧镜像检查，不靠缩小字号或放宽重叠断言通过。缺字体场景只证明几何降级安全，不代表缺失字形仍可读；实际使用仍需系统字体。

另有四个用例覆盖界面与输入闸门：`inputGateAndUiOccupancy`（占屏时命令类动作被拦、界面类动作仍可派发、未知动作被拒、动作表提示与按键同源）、`performanceAndFreshness`（新鲜度分级随数据年龄递进到「已过期」、GUI 线程被人为阻塞时报出并计数、恢复后清除）、`sourceSwitchCost`（UDP 同源短路、冷却期内换源被拒、非法来源编号被拒）、`localVideoReselection`（选择器反复打开、首次取消不改变来源、暂停后取消保留进度、连续换片/同文件重播、无效媒体后恢复与控制锁定）。选片回归使用离屏 Quick 对话框并注入最终选片信号，不代替 Windows 原生文件窗口的人工点击验收。核心策略（新鲜度分级、输入映射语法、切源策略、界面占用闸门优先级）由无 Qt 依赖的 `rm27_core_policies_tests` 与 `rm27_core_tests` 覆盖。

摄像头硬件烟测是可选项，设置 `RM27_TEST_CAMERA=1` 与 `RM27_TEST_VIDEO` 后运行 `build-gui\rm27_playback_tests.exe optionalCameraSmoke`。它会短暂打开第一台摄像头，检查有效帧与主视频同时运行，再关闭摄像头；不会保存摄像头图像。
