# RM2027 自定义终端项目规则

## 独立项目边界

本文件只管理本目录的自定义客户端。以本目录为工作目录，使用本目录的 `CMakeLists.txt`、`run-terminal.cmd`、`scripts/`、`.agents/skills/` 和 `Edit.md`，不得依赖父目录的规则或构建入口。

Python 模拟裁判系统独立维护；客户端只通过明确标注的本机模拟接口接收其数据，不导入模拟器代码、不要求模拟器目录存在。跨项目修改必须先分别完整阅读两个项目的 `CLAUDE.md`，并分别追加各自 `Edit.md`。

`Edit.md` 只在本机保留，不提交或随发布包分发。迁移前的完整历史日志保存在本项目的 `Edit.md`，不得改写。旧构建缓存保存在 `archive/`，新构建使用本目录的 `build-gui/` 或 `build-release/`；旧发布包保留在 `dist/`。

两个项目目前共用父目录隐藏的 Git 历史；本次目录划分不等于创建新的 Git 仓库。工程与启动不得依赖这层 Git 元数据；发布脚本记录来源提交时仍使用现有 Git 仓库。

若 Skill 中仍要求把修改日志写入 CLAUDE，以本文件和 `AGENTS.md` 的 `Edit.md` 规则为准。

## 项目目标

开发一套 Windows 优先、核心可跨平台的 RM2027 重装机器人操作手自定义终端。正式客户端使用 Qt 6、QML、C++ 和 CMake；Python 模拟器与正式客户端分离，用于确定性仿真、回放与联调。

首版只替代重装机器人操作手终端，其他机器人继续使用官方客户端。架构须为未来的综合指挥界面和符合规则的自定义客户端手动切换预留清晰扩展点，但不得提前实现未经确认的协议功能。

### 贯穿各阶段的收尾要求

**当前 M1 实现与下一步：** 普通 `rm27_terminal` 默认编入 `third_party/rm26_client` 的固定 MIT 后端，来源和本地补丁见 `SOURCE.json`/`PATCHES.md`。MqttManager、NetworkManager、GameData 在一个工作线程中运行；订阅 24 个已核验下行主题，连接身份来自启动面板或明确 CLI，红步兵3为数字 ID 3。全部 SUBACK 成功才接收，带单调时间的有效报告由同一个 GameData 提供，HUD 不读取上游默认血量/倒计时和窄化 getter。缺字段不等于零；逐主题 1500ms 过期、身份改变/断线清空、5s 重连重订阅；阈值和队列限额是项目决策。正常启动不自动连接保存的地址，离线/回放停止连接；sim.v1 仍须显式选择自己的模拟入口。QML 只改身份有效性、来源文案和既有回调，布局/资源保持。

M1 软件检查使用普通 exe 的本机 MQTT wire 对端，另检查启动面板红3→蓝3身份切换、离线进入与回放。`RadarInfoToClient` 未订阅；处罚、模块、复活、Buff、性能选择等目前只在有类型状态/原始有效报告中，不能据此解除遮挡或下发。机制/伤害/路径/地图点击/自定义块/工程/哨兵/飞镖/空支援等新增报告缺少既有 UI 展示入口，逐项登记，不擅自增加控件。历史探针保留作独立协议/入站防护回归，默认 OFF，不作为普通 HUD 的第二套后端。随后 **M3** 接指令门/限频/回执；不要因为硬件未到重复做 M0 或新增独立实验 exe。真实对频、现场数据/视频、1080p60、实机指令和长时验收仍是 M4。

**M2 当前实现：** 普通 exe 的 `--protocol rm2026-v2.0.0 --hevc-udp` 直接接现有 VideoOutput。支持视频单独运行，或与明确 MQTT/身份配置同时运行；`run-terminal.ps1 -OfficialUdpVideo` 已转普通入口。必须显式 IPv4 监听地址、固定来源、端口和 fragment-base 0/1；非环回另开 allow-network-video，测试模式只接 127.0.0.1。无参数不监听、不改网卡。复用固定 MIT HevcDecoder 的 parser/send/receive/sws/QImage 和恢复；用已有严格有界组帧替代上游无界/不完整组帧，私有H264分支不引入。匹配 Qt 的 LGPL FFmpeg 7.1.5 公共头与共享 DLL，初始化核验版本；不依赖 DJI、不转码、不新增 exe。独立视频线程，最多一个待提交图像，GUI每16ms取最新帧；150ms组帧期限、2MiB上限、700ms出帧过期、源端口固定至静默后重置。只把实际有效 sink 帧当画面证据，断流清帧/等参数和关键帧，身份配置/离线/回放切换停止旧视频。MQTT和视频各自断链恢复，控制仍禁用。全部阈值是项目决策。

M2 本机验证使用自己生成的 320x180 / 30fps Annex-B 色条，不是硬件画面或1080p60验收；解码、乱序、重复、源拒绝、丢片、无关键帧、过期清帧、恢复、0/1分片、会话切换和原 UI Windows 渲染均需通过。offscreen无RHI只验解码/HUD；窗口像素检查走Windows后端。诊断包含收包/组帧/实际解码数、待图像深度、覆盖/丢弃、解码耗时、解码到提交及GUI呈现数；不声称测得相机端到端。普通入口已接人工配对参数，LOCAL_HUD 合成 HEVC 复用同一 UpstreamVideo/开源 HevcDecoder；HistoricalVideoReceiver、第二 UDP 解码端口、独立 run-rm2026-video.ps1、VIDEO_HUD 分支和 historicalVideo 属性已删除。旧 VIDEO_HUD=ON 缓存拒绝，不能当当前入口；默认OFF的 LOCAL_HUD 数据参考仅保留作协议回归，未称所有历史实验全部删除。**M3已接有类型动作、指令门、限频与传输确认，剩余业务权限和UI入口缺口见下文。**普通Release已有本机独立目录验收；干净机器与实物仍待。详细构建/验收记录只见Edit.md。


M3 按以下顺序推进：先核对11个已验证上行消息与固定开源 NetworkManager 的生成/发送方法，逐项落到已有动作，缺少UI入口的只登记有类型接口；再接唯一指令门和按协议核验的限频，失焦/释放/遮挡/断线/身份或来源切换清旧输入，模拟与回放不能发布到赛事端点；最后用独立本机接收端核对实际 PUBLISH 字节、QoS、频率及已知结果报告。测试发布、broker确认、赛事接受与机器人执行分别记录；地图标定或处罚解除缺口只阻塞对应动作，不补猜字段、不另建实验exe。完成这些软件验收后才进入M4实物联调。

### 参考实现的使用规则

1. 这些仓库都是 **RM2026 期实现**。其中的主题名、地址与端口（如 `192.168.12.1:3333`、`3334`、`0x0310`、300B/50Hz 分片）**一律不得仅凭社区实现进入正式代码路径，也不得表述为 RM2027 协议事实**。用户授权的独立 2026 离线参考仅以官方 2026 通信 PDF 为字段依据，不使用这些仓库填补文档缺口。
2. 允许复用授权明确的通信、状态、视频与业务实现；真实线格式和业务语义须另按对应官方版本核验。队列、恢复、日志与配置等工程策略记录为项目决策。
3. 复制任何代码或素材前，先在 `Edit.md` 记录来源、许可证与署名要求；**无许可证的项目只读不抄**。
4. **架构反例同样登记、同样不得照搬**：例如 `RM26_Client` 的 7000 行 `MainWindow`、QML 直接调用网络层、把 Protobuf 类型暴露给 QML、`IgnoreAspectRatio` 全窗口拉伸、软解 + `QPainter` 渲染路径，以及"模拟器编入客户端且不禁止发送"的做法，都与本仓库「传输/状态/策略/表现层分离」「QML 不解析数据包、不直接发送底层指令」「模拟与回放禁止下发」的约束冲突。
5. 官方通信协议到位后，本节内容不得替代协议本身。
