# RM2027 自定义终端项目规则

## 独立项目边界

本文件只管理本目录的自定义客户端。以本目录为工作目录，使用本目录的 `CMakeLists.txt`、`run-terminal.cmd`、`scripts/`、`.agents/skills/` 和 `Edit.md`，不得依赖父目录的规则或构建入口。

Python 模拟裁判系统独立维护；客户端只通过明确标注的本机模拟接口接收其数据，不导入模拟器代码、不要求模拟器目录存在。跨项目修改必须先分别完整阅读两个项目的 `CLAUDE.md`，并分别追加各自 `Edit.md`。

`Edit.md` 只在本机保留，不提交或随发布包分发。迁移前的完整历史日志保存在本项目的 `Edit.md`，不得改写。旧构建缓存保存在 `archive/`，新构建使用本目录的 `build-gui/` 或 `build-release/`；旧发布包保留在 `dist/`。

两个项目目前共用父目录隐藏的 Git 历史；本次目录划分不等于创建新的 Git 仓库。工程与启动不得依赖这层 Git 元数据；发布脚本记录来源提交时仍使用现有 Git 仓库。

若 Skill 中仍要求把修改日志写入 CLAUDE，以本文件和 `AGENTS.md` 的 `Edit.md` 规则为准。

## 项目目标

开发一套 Windows 优先、核心可跨平台的 RM2027 重装机器人操作手自定义终端。正式客户端使用 Qt 6、QML、C++ 和 CMake；Python 模拟器与正式客户端分离，用于确定性仿真、回放与联调。

首版只替代重装机器人操作手终端，其他机器人继续使用官方客户端。架构须为未来的综合指挥界面和符合规则的自定义客户端手动切换预留清晰扩展点，但不得提前实现未经确认的协议功能。

显式合成开发演示是独立 `scripts/run-rm2026-demo.ps1` / `tests/rm2026_observer_demo.py`：标准库短时环回测试对端，默认只喂自己启动的上述主 HUD（开发验收可指定原 viewer），使用人工报文而非赛事抓包。不部署通用 broker、不占用已有模拟端口、不导入 simulator 源码、不进入正式发布；无事件玩法推断、真实控制或地图映射。测试对端限额与下述原生入站防护分别验收，不能互相替代。普通只读窗口仍不会自产数据。

### VT02 / VT12 实测补充（2026-10-07）

本节更新旧记录中“旧接收端尚无可用码流”的结论，但**不把实测样本提升为官方公开协议**，不改变新版 HEVC 模块。

- 用户成功采集的 `log/vt12-netsh-20261006-222229-598.etl` 含 3109 个 NDIS 报文记录，IPv4 重组得到 312 个完整 UDP 数据报，端点为 `192.168.42.2:58086 → 192.168.42.105:8080`。样本每报文前 8 字节之后为 H.264 Annex-B；去头后 4,379,726 B。FFmpeg 识别 H.264 High / 1280×720；这不是新版 HEVC/3334，也不是 VT03/VT13 输出证明。此前 PktMon ETL 只有元数据、导出零包；以实际 NDIS 载荷为准。
- 该短样本有 SPS/PPS、无 IDR，普通解码不出帧；显式 `showall` 中途恢复后得到实际房间画面。初期参数 / 参考缺失仍有诊断，不能承诺全部帧完整无误或低延迟。8 字节前缀含义、长时序号 / 丢包恢复与设备订阅接口尚未确认，不从开源或抓包猜控制语义。
- 用户授权旧硬件只读桌面实验：`tools/vt12_video_bridge.py` 为独立开发工具，显式实验确认、指定 IPv4 / 源 IP / 端口，非环回另需确认。仅针对上述样本封装剥离前缀，复用**用户已安装、显式指定的** FFmpeg 进程解码并重新编码 MPEG-TS，再给现有 Qt 环回测试播放器；原始流不误当 TS。此转码仅验证图像路径，不是正式低延迟实现。Python / 官方包内 FFmpeg 不加入发布依赖、不复制分发、不修改 Qt 私有实现或官方软件。
- 该样本的开发转码显式使用 60 Hz 输入时间基准（官方旧款规格和样本解码 / 到达节奏支持此选择）；短探测若未指定会退回 25 fps。设置 60 并非端到端延迟或源端新鲜度测量，不能套到其他固件 / 变帧率设备。
- 入口独占绑定，8080 被官方程序占用就退出，不共享、不抢占、不结束官方进程；不对接收端发控制包。输入固定源 IP / 首个有效源端口，队列最多 8 个数据报、固定一秒最多 1000 包 / 4 MiB、已收流后静默 700 ms 或队列满立即退出，需手动重启；这些为项目决策。自动测试限 60 秒，不能据此声称长时稳定性或自动断流恢复。
- 真实抓包转码后的文件已通过现有 QML / VideoOutput 的 1280×720 像素、连续出帧、回放控制禁用与窗口截图检查；这只是**真实样本回放进 HUD**。实验桥另通过本机环回重放真实数据报、输出 TS 再解码及断流退出检查，仍不是当前硬件实时直连验收。UI/QML 不改，既有新版 HEVC/3334 入口保持原状。

### 通用产品约束

- 自定义终端只依赖有线网络和有线输入设备，不增加无线依赖。
- 图像是重装操作界面的主体，在常用 16:9 窗口内目标占据至少三分之二的可用内容面积。
- 最上方使用紧凑的告警与链路状态条；地图/目标提示、允许的赛事操作、当前输入模式放在紧凑底栏或窄侧栏。
- 界面必须美观、克制、易扫视：统一字体与间距、清晰层级、有限强调色、高 DPI 适配，不使用影响判断的装饰。
- 正常、综合指挥、手动切换、模拟、回放模式必须视觉可区分。
- 不得绕过规则规定的图像遮挡、处罚、阶段限制或指令限制。
- 断线、数据过期或切换模式后，不得重放旧输入或旧指令。

## 工程边界

- 本地视频回放使用 Qt Multimedia，当前最低 Qt 版本为 6.9（需要 VideoOutput 清帧接口），本机验证版本为 6.11.2。
- 传输、领域状态、指令策略、输入映射、视频、录制、模拟和 QML 表现层必须分离。
- QML 不直接解析网络数据包，不直接发送底层传输指令。
- 阻塞 I/O、解码、录制和重连循环不得运行在 GUI 线程。
- 所有网络输入和回放文件均按不可信数据处理。
- 真实协议常量必须有官方来源；在此之前仅使用明确命名的模拟接口。
- 依赖保持最少，优先使用标准库和 Qt 自带能力。
- 开发启动/发布工具链由 `toolchain.json` 固定，升级先重新验收；本机自检不得修改网卡、系统 PATH 或关闭未知占用进程。
