# 客户端便携包验收

开发构建固定 Qt 6.11.2 / MinGW 13.1.0 / CMake 3.30.5 / Ninja 1.12.1，版本清单为 toolchain.json。启动前运行 run-terminal.cmd -CheckOnly，只检查本应用依赖与本机端口，不修改系统 PATH、网卡、防火墙。

联调发布时运行 scripts/package-windows.ps1 -TestVideo "原创 MP4 路径" -ReferenceProject "模拟器项目路径"。带 TestVideo 才登记窗口视频回归；要验证实际 UDP 解码，另设 RM27_TEST_TS 为合法 TS 样本。发布构建启用断言测试，不能因 Release 的 NDEBUG 变成空测试。

发布包包含 Qt/QML/FFmpeg/编译器运行库、许可、manifest、测试摘要、依赖哈希清单和 ZIP SHA-256，不包含 Edit.md、用户配置、官方规则 PDF、构建工具或第三方参考项目文件。仅分发有权分享的测试视频。

先运行 scripts/check-windows-package.ps1 -Archive "ZIP 路径"，它在新临时目录验证哈希，隔离 PATH/Qt 路径并检查 DLL 是否从解压包加载；只结束自己创建的检查进程。此检查不替代另一台干净电脑验收，清单中的 cleanMachineVerified 仍为 false。

请在未安装 Qt/Python 的 Windows 10/11 x64 机器逐项确认：

- 解压整个 ZIP 到含空格/中文路径，双击 rm27_terminal.exe，启动面板正常。
- 选择离线演练，HUD 正常；无任何真实指令发送，不要求修改网卡。
- 本地视频的播放、暂停、拖动、结束、错误文件恢复正常。
- 另开独立模拟器包，观察红蓝队、本车、血量、消息及断流过期；视频 TS 和裁判数据独立恢复，控制保持锁定。
- 没有 UDP 默认端口冲突；若被占用先退出你自己开的另一会话，不杀未知进程。
- 摄像头硬件验收只在你明确准备采集时手动打开，关闭后停止采集。
- 记录系统版本、显卡/驱动、包 SHA-256、通过/失败项目和日志；H.265 未验证不勾通过。

完成后才能单独记录“干净机器验收通过”；不要直接改归档内 manifest，修改会破坏哈希。新增验收报告与新的发布记录关联即可。这里是操作清单，不是已执行结果。
